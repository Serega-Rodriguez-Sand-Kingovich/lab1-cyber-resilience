## Введение

Лабораторная работа продолжает единый ML-проект по распознаванию рукописных цифр 8×8. Модель из ЛР №2 с baseline accuracy 0,974138 была подготовлена и проверена в CI ЛР №3. Цель ЛР №4 — предоставить ограниченный веб-доступ к предсказаниям без переобучения, реализовать аутентификацию и защиту от некорректных запросов, организовать структурированное наблюдение за отказами и показать контролируемый сценарий обнаружения с восстановлением.

## 2. Сервер и API

FastAPI с endpoints `/predict`, `/health`, `/`, `/metrics`, `/detection`. Модель сверяется с доверенным эталоном до десериализации, затем передаётся отдельному subprocess-worker при старте. Формат входа — JSON-матрица пикселей 8×8 в диапазоне [0,16]. Успешный `/predict` возвращает цифру, версию и request_id. Неготовый `/health` возвращает 503.

- Скриншот №2: `GET /health` → HTTP 200.
- Скриншот №3: автоматический тест повреждённого SHA256 → `/health` HTTP 503.

## 7. Контейнер и CI

Docker-образ работает от UID 10001, без root, контейнерный HTTP слушает порт 8000, который публикуется на loopback Ubuntu; доступ с Windows предоставлен через SSH. CI сохраняет gates и сканирование ЛР3, выполняет тесты API, контейнерный smoke `/health` и `/predict`, не содержит пользовательских ключей.

## Вывод

В рамках ЛР №4 прежняя ML-модель была предоставлена через контролируемый HTTP API с проверкой контрольной суммы перед десериализацией. Реализованы проверка формы и размеров запросов, аутентификация, локальный rate limiting, интерфейс для числовых изображений, структурированные логи и метрики. Сценарий контролируемой серии отказов демонстрирует срабатывание правила наблюдения и возвращение штатного режима после окончания окна. Ограничения учебной реализации: limiter/метрики в памяти одного worker, отсутствие production-доступности и измерения устойчивости классификатора к новым атакам.
